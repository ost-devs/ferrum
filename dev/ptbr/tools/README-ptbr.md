# Ferramentas

Ferramentas compartilhadas do workflow ([`docs/workflow/`](../docs/workflow/)). Rode todo comando a partir da raiz do repositório. Conferidas em 2026-11-07 contra `@codemirror/state`: 264 linhas de inventário, 172 casos de teste. Node 22, `tsx`, Python 3.

| Ferramenta | Usada em | Comando | Saída |
|---|---|---|---|
| [`tools/cm6/setup_harness.py`](../../../tools/cm6/setup_harness.py) | especificação S0, uma vez por crate | `python3 tools/cm6/setup_harness.py <pacote> [--npm <pkg@ver> …]` | `.harness/<pacote>/` (no gitignore): cópias do `src/` do pacote e de todo pacote `@codemirror/*` de que ele depende, suas dependências npm, TypeScript, um `tsconfig.json` que mapeia `@codemirror/<nome>` para as cópias, `@harness/lib` para [`tools/cm6/oracle-lib.ts`](../../../tools/cm6/oracle-lib.ts) e `@harness/program` para [`tools/cm6/program.ts`](../../../tools/cm6/program.ts), `harness.json` com as versões. `tsc -p .harness/<pacote>` confere os tipos dos arquivos do oráculo e de `tools/cm6/` (`tsx` os roda sem conferir); é uma ajuda para quem os escreve, não um portão: filtre a saída pelo diretório em que você trabalha |
| [`tools/cm6/oracle-lib.ts`](../../../tools/cm6/oracle-lib.ts) | toda sonda, todo gerador e todo interpretador | `import {rng, capture, encode, decode, unstable, fixtureWriter, runIsolated, isolatedMain} from "@harness/lib"` | gerador pseudoaleatório com semente (mulberry32), captura de exceções, a única codificação de valores que o JSON não comporta ([`docs/workflow/specification.md`](../docs/workflow/specification-ptbr.md) §4: `encode`, sua inversa `decode` para um interpretador que lê uma entrada, `unstable` para um valor que difere entre execuções), o escritor de fixtures, que codifica toda entrada e saída, execução de uma sonda que pode não terminar em um processo filho com limite de tempo que não sobrevive a esse limite |
| [`tools/cm6/program.ts`](../../../tools/cm6/program.ts) | o interpretador de todo chunk | `import {Language, Program, markRead} from "@harness/program"` | a única linguagem das entradas de fixtures ([`docs/workflow/specification.md`](../docs/workflow/specification-ptbr.md) §5 item 3), documentada no topo dela: programas e expressões soltas, passos, variáveis, `if`, o template `out`, as ops que não tocam nenhum valor do cm6, `map`, `try`; o registro em que o `interp.ts` de um chunk registra cada uma das suas ops com seus kinds e exporta `lang` e `run` |
| [`tools/cm6/replay.ts`](../../../tools/cm6/replay.ts) | rodado por [`tools/spec_check.py`](../../../tools/spec_check.py) | `npx tsx --tsconfig .harness/<pacote>/tsconfig.json tools/cm6/replay.ts <crate> <chunk> …` | uma linha JSON por chunk: toda entrada gravada reproduzida pelo `lang` do seu chunk enquanto cada chave lida é registrada (o cabeçalho dele lista os campos) |
| [`tools/cm6/replay.ts --trace`](../../../tools/cm6/replay.ts) | quando uma fixture falha num crate; rodado por [`tools/trace_diff.py`](../../../tools/trace_diff.py) | `npx tsx --tsconfig .harness/<pacote>/tsconfig.json tools/cm6/replay.ts <crate> --trace <chunk> <id da fixture>` | uma linha JSON por op que o programa da fixture avaliou no cm6, na ordem em que as avaliações começaram (`n`, `depth`, `op`, `kinds`, `value` ou `threw`; uma instância de classe do cm6 como `{"cm6": name}`), depois a saída e se ela é igual à gravada. O `lang` do chunk nomeia os casos de [`tools/cm6/lang-cases.jsonl`](../../../tools/cm6/lang-cases.jsonl) |
| [`tools/cm6/lang-cases.ts`](../../../tools/cm6/lang-cases.ts) | quando [`tools/cm6/program.ts`](../../../tools/cm6/program.ts) muda; sua forma `--check` é rodada por [`tools/spec_check.py`](../../../tools/spec_check.py) | `npx tsx --tsconfig .harness/<pacote>/tsconfig.json tools/cm6/lang-cases.ts [--check]` | [`tools/cm6/lang-cases.jsonl`](../../../tools/cm6/lang-cases.jsonl): 47 programas que usam só as ops da linguagem (nenhum valor do cm6), cada um com a saída que `program.ts` deu. A referência do replayer de fixtures de um crate: o avaliador dele precisa dar essas saídas antes de se escrever qualquer op de um chunk. `--check` falha quando o arquivo commitado não é o que a execução dá ou quando uma op da linguagem não é rodada por nenhum caso |
| [`tools/trace_diff.py`](../../../tools/trace_diff.py) | implementação, quando uma fixture falha | `python3 tools/trace_diff.py <crate> <chunk> <id da fixture> <arquivo com as linhas de trace do replayer>` | roda a fixture no cm6 com `--trace` e compara com as linhas que o replayer do crate imprimiu para ela: a primeira avaliação que difere, a mais interna primeiro, os dois valores, e se essa op toca o crate de algum modo (uma op só de kind `harness` não toca: a diferença é então do replayer). Sai com 0 quando as execuções concordam |
| [`tools/cm6/inventory.cjs`](../../../tools/cm6/inventory.cjs) | especificação S0 | `node tools/cm6/inventory.cjs --harness .harness/<pacote> --package <pacote> --prefix <crate>.cm6 > docs/parity/<crate>/raw/inventory.jsonl` | uma linha por export, membro público e campo de objeto de configuração |
| [`tools/cm6/tests.cjs`](../../../tools/cm6/tests.cjs) | especificação S0 | `node tools/cm6/tests.cjs --harness .harness/<pacote> --package <pacote> > docs/parity/<crate>/raw/tests.jsonl` | uma linha por `it()`, `webtest-*` incluídos; `generated: true` marca casos criados em laços (expanda-os, uma linha por caso) |
| [`tools/spec_synth.py`](../../../tools/spec_synth.py) | quando alguém precisa ler as linhas como tabelas | `python3 tools/spec_synth.py <crate> <curto> <pacote cm6> <versão> <commit do espelho> stack contracts hazards views` | sob `.scratch/views/<crate>/`, nunca commitado: notas de pilha e riscos agrupados por item, a tabela de throws, e as linhas de `raw/inventory.jsonl`, `raw/behaviors.jsonl`, `raw/tests.jsonl` como tabelas |
| [`tools/render.py`](../../../tools/render.py) | qualquer | `python3 tools/render.py <linhas.jsonl> --cols id,item,… [--title …] [--header …] > <arquivo>.md` | tabela Markdown a partir de JSON Lines |
| [`tools/spec_check.py`](../../../tools/spec_check.py) | etapa de especificação, item 1 da verificação ([`docs/workflow/specification.md`](../docs/workflow/specification-ptbr.md#8-verificação) §8), e depois de qualquer mudança em linhas, fixtures ou geradores | `python3 tools/spec_check.py <crate> [--no-run] [--chunk <nome>] [--same-outputs-as <ref do git>]` | contagens, ids duplicados e pendentes, itens sem comportamentos, comportamentos sem fixtures; todo gerador rodado de novo na ordem de `oracle/cm6/order.json` numa cópia de scratch e comparado byte a byte; cobertura do cm6 por essas execuções, as linhas e ramos não alcançados em `raw/coverage.jsonl` (o fim sem mapeamento de cada módulo compilado, que nunca roda, é descartado e contado); quando `verification.md` tem uma seção `## Coverage`, uma falha para cada ponto não alcançado que ela não nomeia; com `--same-outputs-as`, item, comportamentos e saída de toda fixture comparados com um commit, as saídas como valores (uma forma anterior à codificação única é lida como o valor que representava; um valor que o JSON antigo não comportava pode agora ser exato, e é contado); o replay de toda fixture, uma linha por chunk cujas contagens depois da primeira precisam ser zero (saídas que diferem, chaves que nada leu, texto de chamada sob uma chave descritiva, um literal em `out`, nenhuma op de kind `api` ou `internal`, ops sem kinds ou não nomeadas no cabeçalho do interpretador, `eval` ou `Function`: o docstring da ferramenta diz o que cada uma significa), uma segunda linha por chunk para as fixtures que terminam num throw não capturado (onde o cm6 lançou é guardado ao lado da execução, não na saída: qualquer um lançado em lugar sem linha em `raw/throws.jsonl` falha), e `raw/fixture-ops.jsonl`; a contagem dos valores ainda numa codificação anterior, por chunk; os casos da própria linguagem reproduzidos (`tools/cm6/lang-cases.ts --check`). 84 segundos para `ferrum-state` em 2026-11-13, 172 segundos numa sessão na nuvem em 2026-11-14 |
| [`tools/spec_facts.py`](../../../tools/spec_facts.py) | especificação S5, fatos para o consultor | `python3 tools/spec_facts.py <crate>` | sob `.scratch/s5/<crate>/`, nunca commitado: para cada op cujos kinds não são só `api`, as chaves de objeto das saídas das fixtures que a rodam; para cada linha de `raw/throws.jsonl`, as fixtures cuja execução termina num throw não capturado na linha dela |
| [`tools/ledger.py`](../../../tools/ledger.py) | depois de toda execução, e a cada revisão do método | `python3 tools/ledger.py add <tipo> chave=valor …`; `python3 tools/ledger.py report [<crate>]` | acrescenta a `docs/progress/ledger.jsonl` (execuções, defeitos escapados, mudanças de método com a medição que deve confirmá-las, resultados); o relatório imprime tokens por passo, escapes por passo e as expectativas ainda abertas |
| [`tools/check_refs.py`](../../../tools/check_refs.py) | fim de todo passo que escreve documentos | `python3 tools/check_refs.py docs .claude tools --quiet` | contagem de referências que não resolvem (caminhos de rascunho, arquivos faltando, linhas além do fim, seções faltando). Um documento que nomeia caminhos que o trabalho ainda vai criar os declara numa linha `<!-- refs:planned <caminho> … -->`; eles são contados como planejados enquanto faltam, e a linha é relatada como `STALE` quando um caminho passa a existir |
| [`tools/ferrum_pub.py`](../../../tools/ferrum_pub.py) | conformidade G1 | `RUSTC_BOOTSTRAP=1 cargo rustdoc -p <crate> -- -Z unstable-options --output-format json`, depois `python3 tools/ferrum_pub.py target/doc/<crate_name>.json crates/<crate> > pub.jsonl` | itens públicos de um crate do Ferrum. Escrito para o formato 61 do JSON do rustdoc: confira `format_version` antes e adapte se tiver mudado |

Rode uma sonda com `npx tsx --tsconfig .harness/<pacote>/tsconfig.json <sonda>.ts`. As sondas importam o cm6 pelo nome do pacote (`@codemirror/state`) e os helpers como `@harness/lib`; elas ficam em `docs/parity/<crate>/oracle/cm6/<chunk>/`. Os mirrors em si são buscados pela skill `mirrors` (`/mirrors`).
