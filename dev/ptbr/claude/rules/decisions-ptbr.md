# Decisões em vigor para o código dos crates

Decisões que o código dos crates deve seguir e que vão além de um único item do cm6 ([`docs/workflow/README.md`](../../docs/workflow/README-ptbr.md#3-decisões) §3). Decisões sobre um único item do cm6 ficam na linha desse item na especificação; o projeto de um crate fica no `docs/parity/<crate>/design.md` dele; como os nomes do cm6 viram nomes em Rust fica em [`.claude/rules/rust-naming-decisions.md`](rust-naming-decisions-ptbr.md). Só o agente `consultant` ou o mantenedor acrescenta ou muda uma entrada, junto com o seu registro em [`docs/decisions/foundation.md`](../../docs/decisions/foundation-ptbr.md). Os ids são estáveis e são o que as anotações citam ([`.claude/rules/rust-crates.md`](rust-crates-ptbr.md) "Anotações"). `D1`–`D10` são as decisões fundamentais de [`docs/foundation/ferrum-foundation.md`](../../docs/foundation/ferrum-foundation-ptbr.md#6-decisões-fundamentais-antes-de-qualquer-implementação) §6; `D11` em diante são as posteriores. Cada entrada diz a que se aplica.

| Id | Decisão | Motivo | Aplica-se a |
|---|---|---|---|
| D1 | Uma posição, comprimento ou deslocamento conta bytes UTF-8 do documento, no qual toda quebra de linha conta um, qualquer que seja o separador que a fonte usou. Uma posição fica numa fronteira de `char`; uma que não fica é uma precondição violada (D13). Valores gravados do cm6 são unidades de código UTF-16 e são convertidos através do texto a que se referem, nunca à mão; uma fixture do cm6 cuja posição cai dentro de um caractere não tem contrapartida no Ferrum e é listada | O cm6 conta unidades UTF-16 porque esse é o índice de string do seu runtime; o que o editor precisa é que uma posição indexe strings e árvores de sintaxe diretamente, o que em Rust (`str`, regex, tree-sitter, shapers de texto) é o byte | todo crate: assinaturas, testes, o replayer de fixtures |
| D2 | `Text` é a árvore de linhas do cm6, portada com a sua forma (folhas de no máximo 32 linhas, `children`), sem biblioteca. As linhas são guardadas como dadas, sem a sua quebra; uma quebra conta uma posição. As strings são divididas em `\r\n?\|\n`, ou no `lineSeparator` exato quando há um, e unidas com `"\n"` ou com esse separador. Os grapheme clusters seguem `@marijn/find-cluster-break` na versão fixada, portado com a sua tabela, atrás de uma só função, até a melhoria `state.imp.001` (os extended grapheme clusters da UAX #29) substituir essa regra no delta de melhorias do `ferrum-state` (D16) | O cm6 expõe a forma da árvore e seus testes a leem; suas strings de linha são o que os crates de cima indexam. As regras de cluster do cm6 são o piso: são mostradas exatamente primeiro, e a regra Unicode, que é melhor para a pessoa que edita, depois as substitui como uma diferença medida | `ferrum-state` (`text`, `char`, `column`), todo crate que avança por cluster |
| D5 | `StateCommand` é `dyn for<'a> Fn(StateCommandTarget<'a>) -> bool + Send + Sync`, com `StateCommandTarget { state: EditorState, dispatch: &mut dyn FnMut(Transaction) }`; retorna se foi aplicado, como no cm6. O `Command` que recebe a view é decidido com o `ferrum-view` | O contrato do cm6 (ler o estado, talvez despachar, informar) e o literal `{state, dispatch}` dos seus testes passam sem mudança | `StateCommand` do `ferrum-state`; comandos nos crates de cima |
| D6 | Todo valor público da fundação é imutável, barato de clonar e `Send + Sync`; callbacks e valores que um usuário fornece são `Send + Sync + 'static`. Um crate da fundação não inicia thread a menos que a sua própria decisão diga, e não guarda estado global mutável além de contadores de id. Um estado em construção só é visível na thread que o constrói. Os ids seguem a ordem de definição | O estado do cm6 já é imutável; compartilhá-lo deixa o parsing, a busca e a indexação lerem um snapshot fora da thread principal, o que não pode ser acrescentado depois sem quebrar a API | todo crate da fundação |
| D9 | Licença por crate: MIT; Apache-2.0 só para um crate que porta ou incorpora código Apache-2.0; os crates de fundação são MIT. Nenhum código copyleft lido, copiado ou usado como dependência | Decidido pelo mantenedor, 2026-11-04 (`ferrum-foundation.md` §6 D9) | manifestos dos crates, dependências |
| D11 | O comportamento do cm6 é o piso. Ele é reproduzido como o cm6 o produz para toda entrada que os tipos do Ferrum conseguem expressar, inclusive resultados que parecem não intencionais, a menos que uma decisão registrada para o item permita uma diferença. Dois tipos de decisão permitem. Um *desvio* (`docs/parity/<crate>/raw/decisions.jsonl`), em três classes: (a) o cm6 não termina; (b) o resultado precisa de identidade de objeto do JavaScript de algo que em Rust é um valor, ou da mutação de um objeto depois de entregue (um array de quem chama, um estado anterior); (c) o resultado vem de o JavaScript ler além do fim de uma string ou array, ou calcular com `NaN` ou `undefined`. Uma *melhoria* (D16) | O piso é o que o cm6 faz, o oráculo diferencial compara toda entrada, e "parece não intencional" não é evidência; as três classes são as que nenhum valor de Rust consegue reproduzir ou nenhuma verificação consegue afirmar; uma melhoria traz evidência própria | todo código de crate |
| D12 | Entrada que só existe porque o JavaScript não tem tipos é excluída pelo tipo: uma posição, comprimento, contagem ou índice negativo, fracionário, `NaN` ou infinito; um valor de tipo errado (um não-função onde se espera uma função, `null` por um objeto, uma string por um número); uma chave além dos campos de uma struct tipada; uma string com um surrogate solitário. Posições, comprimentos e números de linha são `usize`. Nenhuma API é alargada para aceitar tal entrada | A única guarda do cm6 para isso é o TypeScript; os resultados são artefatos do motor que nenhum chamador usa (nenhum consumidor espelhado passa uma), e uma assinatura de Rust não consegue expressá-los | assinaturas públicas; quais fixtures o replayer roda (`D13` para leitores de JSON) |
| D13 | Erros. Onde o cm6 lança exceção numa precondição, o Ferrum falha na mesma condição: faz panic, com a mensagem que o cm6 dá (seus números nos valores do Ferrum), documentada em `# Panics`. A exceção é um leitor de dados serializados (`from_json`), que retorna `Result<_, Error>` e também retorna `Err` para um número JSON fora do domínio de `D12`, onde o cm6 o aceita. Toda falha assim é uma variante do enum `Error` do crate, cujo `Display` é a mensagem do cm6; a classe de erro do JavaScript (`RangeError`, `Error`) não é portada. Onde o cm6 falha com um `TypeError` do motor numa entrada que os tipos do Ferrum conseguem expressar, o Ferrum faz panic na mesma condição com uma mensagem própria. Um callback de usuário que falha faz panic, e o panic se propaga | Todo throw explícito do cm6 guarda uma condição que quem chama pode testar antes, então uma falha é um bug de quem chama, que o Rust informa com panic (indexação de `slice`, fatiamento de `str`); o código acima deste crate deriva suas posições do estado que tem e retorna `bool` (comandos), então um `Result` ali seria desembrulhado a cada chamada. Dados serializados vêm de fora do programa. Uma variante que não faz panic pode ser acrescentada depois sem quebrar quem chama; o inverso não | assinaturas públicas, comentários de documentação, a comparação de erros do replayer |
| D14 | Formas em Rust de formatos do JavaScript. Um parâmetro que o cm6 torna opcional é um parâmetro obrigatório: do seu próprio tipo quando o padrão do cm6 é um valor (quem chama escreve o padrão), `Option<T>` quando o cm6 distingue "ausente" de todo valor. Um objeto literal com campos opcionais é uma struct com campos públicos e `Default`, cada padrão sendo o do cm6. Um parâmetro de tipo união é um enum ou `impl Into<…>` que mantém todo membro expressável. `===` e `==` em valores são o `PartialEq` do tipo em Rust: igualdade de valor para números, strings e booleanos, e um tipo que o cm6 compara por identidade de objeto (uma função, um objeto de definição como uma facet) implementa `PartialEq` por ponteiro. Um argumento callback é `Fn`, chamado na ordem e no número de vezes em que o cm6 o chama, com argumentos na ordem do cm6 | Uma regra por formato mantém as assinaturas mecânicas em quatro crates; uma segunda forma de conveniência de uma função é API além da especificação e pode ser acrescentada depois sem quebrar quem chama | assinaturas públicas |
| D15 | Membros do cm6 marcados `@internal` que os seus testes ou as fixtures leem. Um formato de depuração (`ChangeDesc.toString`) é a implementação de `Debug` do tipo. Qualquer outra coisa é exposta só num `#[doc(hidden)] pub mod __test`, compilado sob a cargo feature `__test` (desligada por padrão, nunca ativada pela fachada), com o nome da exportação `__test` do próprio cm6; os testes do crate a ativam | Os testes portados e o replayer ficam fora do crate e são os mesmos testes do cm6 ([`.claude/rules/rust-crates.md`](rust-crates-ptbr.md) Testes 1, 6); a saída de `Debug` não é promessa de API em Rust, e uma feature mantém os internos fora de todo build de aplicação | itens `@internal`, `crates/*/tests/` |
| D16 | Melhorias sobre o cm6. Onde o Ferrum pode servir melhor do que o cm6 a pessoa que edita ou a aplicação que o embute (correção, capacidade, ergonomia), a oportunidade é uma linha de `docs/parity/<crate>/raw/improvements.jsonl`, escrita pelo consultor e nunca abandonada por amor à imitação: `adopted`, `scheduled` com o ponto em que é feita, `candidate` com o ponto em que é avaliada, ou `declined` com um motivo que não seja fidelidade ao cm6. O código difere do cm6 para melhor só sob uma linha `adopted`, anotado `/// cm6 deviation: <o que difere>, see <id da linha>`, e só quando a referência da linha roda: o cm6 com a melhoria aplicada como patch no harness, ou os dados de teste do padrão que a linha nomeia, dá os valores esperados onde o Ferrum e o cm6 diferem. Uma melhoria que substitui um comportamento do cm6 é feita como delta sobre código já mostrado igual ao cm6, a menos que fazê-la depois quebrasse a API pública ou dados armazenados, caso em que ela faz parte do projeto do crate. Um implementador que vê um jeito de fazer melhor do que o cm6 o levanta como pergunta e implementa o comportamento do cm6 | A intenção do mantenedor: o cm6 é o piso, nunca o teto, e nenhum jeito de ser melhor é deixado passar em silêncio; uma mudança drástica feita às pressas não é desejada. Uma referência que roda mantém a prova onde estava, e um delta sobre um piso provado mostra que a melhoria mudou o que a sua linha diz e nada mais | todo código de crate; `crates/*/tests/`; o replayer de fixtures |
