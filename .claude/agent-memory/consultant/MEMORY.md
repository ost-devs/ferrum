## Precedents
- Who frames a decision: producers bring facts and questions, never options or proposals; I build the alternatives (anchoring; approval is weaker than derivation). `docs/decisions/method.md`, 2026-11-08
- Which cm6 is the reference: published releases, not `main`; reason: parity serves what users run. `docs/decisions/foundation.md` Q4
- Deferring cm6 items in bulk (D10-like): no; leave items out only by their own disposition, listed in every verdict (intent: no silent skips). `docs/decisions/foundation.md` D10
- Where a decision lives: by who acts on it, never gathered for its own sake (one place per decision is not one place for all). Item -> row; crate design -> design.md, its stage procedure -> plan.md; names -> naming file; several crates -> decisions.md, scoped to their paths. An observable deviation needs a citeable id. `docs/decisions/foundation.md`, 2026-11-09 Q2 and "names keep their own file"
- Instruction limits (card size, file counts): replace proxies with a criterion plus a report that measures both gaps (missing, unused). `docs/decisions/method.md`, "method review before the first run"
- Overlapping stages or crates: no while the method is still being refined; correctness over speed. Same entry
- Binding text with no decision record (inherited rules, registry rows): re-derive from facts before relying on it; a category rule must be checked against every member it covers. `docs/decisions/foundation.md`, "the naming entries N1-N5"
- DROP vs CORE for TS/JS-shaped items: DROP only what has no runtime meaning or only builds a JS artifact (phantom `tag`, conformance getters, `fromCodePoint`); keep type-level guarantees (FacetReader), language protocols (`Symbol.iterator`) and anything taking a position (D1 reaches it). A protocol member (`StateField.extension`) is CORE even if Rust's form is static; DROP must not presuppose the S5 design, and "nobody reads it" needs a search covering untyped reads. `docs/decisions/ferrum-state.md`, S1 dispositions and Q53
- A row field's criterion: define it by what its consumer needs (which assertion an answer changes), add a mechanical check; a sample-found rule-wide error is fixed on all rows. `docs/decisions/method.md` M3
- Worker effort: pinned in each definition (session default and the spawn parameter change it silently); the level follows what shows a step's errors (a deterministic check before merge -> medium allowed; omissions nobody sees -> high), not the role; a paired run only to move a silent-error step. `docs/decisions/method.md`, 2026-11-13 "method after the ferrum-state specification"
- Verification by sampling: never "until clean" (a small clean sample proves little, and the loop cost 4x the audit). Order: tool for what is deterministic, independent reading of every item for what only reading shows, one sample as a measurement with rates by severity. Classify findings myself before accepting a summary of them (13 of 29 "prose" defects were about behavior). Same entry
- Stage briefs written before the stage's inputs exist: keep only what parity cannot be shown without; derive the procedure per crate from what the earlier stage produced, first unit as a measured pilot. Same entry
- A stated tool limit (docs, an earlier note, the maintainer's own decision's premises): read the mirrored page and try it before relying on it; three of four such limits were wrong or narrower on 2026-11-13 (`docs/workflow/README.md` §8)
- What workers lack is the purpose of each field (who reads it, what a wrong value causes), not the decider's whole context; checkers get purpose and sources, never the author's reasoning. `docs/decisions/method.md`, 2026-11-13 "method after the ferrum-state specification" (M19)
- Whole-system review (2026-11-13): start from what proves the result (runs of cm6, replay, differential), then ask of each artifact who consumes it and how its error would show; delete what repeats or serves nobody; keep names and paths when the content can be made right in place. `docs/decisions/method.md`, 2026-11-13 "The system realigned"
- A record that must be found later is a file, never a commit message (shallow clones, no translation, not citeable). Same entry
- Before designing a check, write the tool and run it: 84 seconds of tool replaced the mechanical half of six verifier runs and gave a fact (coverage) no agent had produced. Same entry
- Keeping agents out of files: a permission deny (it also filters searches), plus one line of text only for what it cannot see. `docs/decisions/method.md`, 2026-11-08 "dev/ptbr is closed"
- Completeness of a recorded input: replay it with read tracking (every key consumed), never a list of keys that may hold text; and every consumer of fixtures gets one language, not one dialect per chunk. Before relying on a check design, prototype it on the pilot's output. `docs/decisions/ferrum-state.md`, "Step A after the pilot"
- cm6 result that looks like a bug: reproduce it, unless cm6 hangs, the result needs object identity or mutation after hand-over, or it is NaN arithmetic; nobody's "this looks unintended" is evidence, and the oracle pays for every exception. `docs/decisions/foundation.md` D11
- Panic or `Result`: ask who can check the condition first and what the callers above return; prefer the choice that can be extended later without breaking (panic now, fallible variants later). D13
- Many questions of one crate are a few questions asked many times: find the classes first, decide each once as a rule, then write only the per-item consequence. Same entry
- A check that fails on form while the values are equal (Q58): fix the check to compare what it is for, count the accepted form, and close the hole the worker's workaround opened; try a broader check on the committed chunks before adopting it (the general one had false positives). `docs/decisions/ferrum-state.md` Q58
- Design before the foundational drafts are confirmed: write it whole, mark the sections that rest on a draft as not in force, never copy a draft's answer into a rule.
- cm6 result that looks worse than it could be: keeping it is the floor, never the end of the question. Open a row in the crate's `raw/improvements.jsonl` (adopted, scheduled, candidate with a date, declined for a reason that is not fidelity). Never write "no goal asks for it". `docs/decisions/foundation.md`, "cm6 is the floor"
- When to make an improvement: in the design only if making it later breaks the API or stored data (D1, D6); otherwise as a delta right after the crate's conformance verdict, one at a time, before the crate above is specified. Reason: the delta on a proven floor shows exactly what changed. Same entry
- A difference on purpose in a suite of recorded values: never a skip list or hand-written values; patch the reference (cm6 in the harness), let a tool compute which cases change and their new values, fail on a change outside the row's behaviors. Try the patch on the existing replay before relying on it (one file, 126 of 3,823 fixtures). `docs/decisions/method.md`, same date
- A decision the maintainer delegates with "either answer is approved": still derive it, and say what is unknown; "better" in a draft followed by "but parity" is the pattern they corrected.
- A tool that replaces a reading: write the verdict's whole assertion and check the run decides each part (panics: a run shows message and function, not the condition; M33 missed it). A tie or attribution that can err both ways: take each source in the direction whose error shows. `docs/decisions/method.md`, 2026-11-27 "What a tool that replaces a reading must show"
- A patch of cm6 writes Ferrum's observable result, never its mechanism (identity): what the replayer leaves out stays cm6's. Same entry
- A comment serving two checks (G3 literals and the label): before removing it for one, ask what the other loses. `docs/decisions/ferrum-state.md` Q146
- A living file that drifts though its rule exists: find why the rule lost (the cheapest edit was an append; nothing showed the drift), give each fact one home the file points to, make the drift data show fail a check at the write, read for the rest at end of stage. Dormant re-entry knowledge is the crate's directory and the append-only records, never a file every session loads; memory keeps what applies to the next crate. `docs/decisions/method.md` "M34 to M38"
- An overturn that refutes a premise: carry it by a search of every line's evidence for the overturned place, judged with the counterexample; blind re-reads re-derive shared misreadings, and my own classification missed one (change:262). Where a reading's errors all fall in one part of its assertion, ask if that part is data (panics `--reach`). `docs/decisions/method.md`, 2026-11-27 "A refuted premise is carried by search"
- Which Rust function calls which: the compiler's MIR, never a walk by name (three tools patched one cause three ways); dyn/generic Fn by argument types; check against run-observed pairs. A list feeding a reading: discharge pairs through a universal reason so the inner function is judged once. `docs/decisions/method.md` 2026-11-27 "A call graph of Rust code is the compiler's"
- A rule's reach is its reason's, not its predicate's: D1 guards a byte inside a character, so a position past the end follows cm6's code for the call though `is_char_boundary` is false there. A stricter Ferrum check outside the reason is an improvement row, not the rule. `docs/decisions/foundation.md` "D1: a position beyond the document"
- A known defect's fixture stays failing until its fix (no expected-failure list): name the exact failing set in each intervening card. `docs/decisions/ferrum-state.md` "Q155 and Q156"

## Calibration
- 2026-11-13: I read parity as imitation (D2 draft: "the Unicode rule would be better, but no goal asks for it"). The maintainer: parity is cm6's quality, capability and stability or better; cm6 is the floor. They want every improvement visible and its timing mine, not theirs; they do not want drastic changes in a hurry. They weigh stability of the whole above an early gain.
- They confirm drafts readily when the draft states costs; what they push back on is a value judgment of mine presented as a technical one.
- 2026-11-19: I replaced branch coverage with mutation because the sandbox had no nightly; they corrected the criterion, not the check: the environment is theirs to extend on request, never a reason.
- 2026-11-14: they want tools and judgment balanced case by case, said twice that it is not "replace 100%"; they want the method's history as training for AI readers, form mine.
- [Maintainer's suggestions](feedback-maintainer-suggestions.md) — weigh, don't obey or reject for show; they prize decider independence and nothing silent
