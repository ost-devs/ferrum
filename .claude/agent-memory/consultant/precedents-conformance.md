Precedents moved out of the index to keep it short. Each points at its record; re-check before relying on one.

- Approving a specification: say what it does not claim. Residual risk = the samples' high rate times the items nobody read twice, then what stands against it; a wrong row weakens the description, not the proof, when outputs come from runs and coverage is by branch. `docs/decisions/ferrum-state.md`, "S5, third part"
- A reviewer's broad "could the checks hide X" question: ask where a divergence of that kind goes unseen with the plan as written and change only there; reading the plan against its own register found G10 never run and an improvement's evaluation point missing. `docs/decisions/ferrum-state.md` "Q121 to Q129"
- Tool versions: pin what runs Ferrum's own checks (lints, rustdoc format, Rust's Unicode), since their meaning drifts; never pin the engine that writes the reference: make the data hold only what results depend on, so regeneration alarms on a real change. Try the pin before deciding. `docs/decisions/method.md` M22
- A panic in an embedded engine: the floor is cm6's stability (the view catches extension code, the browser contains the rest); catch where cm6 catches, outside data through `Result`, keep the panic for a caller's bug. `docs/decisions/foundation.md` Q128
- API stability before the facade: provisional; only the cost of a change (call sites, cm6 familiarity, mid-stage risk) keeps a form, never that it is written. Same file, Q129
- A type that only carries an argument into one call is no "public value" of D6: check D6 through what the call keeps, accept such types by a named list with their member, failing when stale. `docs/decisions/foundation.md` 2026-11-24 D6
- A difference on a fresh case is attributed to a decision by a run (the row's rule kept as a patch of cm6, validated by reproducing its committed list), never by reading: the first reading misfiled 1 of 3 kinds. Rows no patch can write: a tool check from the row's own sentence. `docs/decisions/ferrum-state.md` "Q130 to Q134"
- A decision row for D1's arithmetic (a distance measured on one stretch, walked on another): find its condition as a class by a model run in both units over random cases, never from the instance; the narrower "where it binds" condition missed cases. Re-derive a left-out kind's values outside the replayer (a reading misplaced one insertion). `docs/decisions/ferrum-state.md` "Q135, Q136 and the U1 findings"
- A mutant that changes a value no check reads (tree shape, a cached length): coverage cannot see it (the line ran); close it with fixtures from cm6 runs, then rerun the mutants. Same entry
- A hazard a decision leaves without counterpart is `EXCLUDED` (cite the decision and the form), one cm6 cannot observe `UNOBSERVABLE` (cite cm6); TypeScript `readonly`/`private` are erased, never evidence. `docs/decisions/ferrum-state.md` Q137 to Q140
- A `usize` bound cm6 only compares takes every value with cm6's result (callers write `usize::MAX`); held lengths are bounded at construction and outside-data readers, not at each cast; an engine stack overflow is a hang (D11 a), reference cm6 on a large stack. D17, same entry
- A verdict-writing run's own work follows the lines it writes (~28k + ~324 a line), not its reading; check what the assignments computed against what the plan says, fit on every finished run of the kind. M29
- cm6's null/undefined stand-ins (loose `==` with a missing lookup, the null of an uncomputed slot) where Ferrum's type has no such value: D11 (c) row + patch, run on cm6 first; a design promise is made true by a check. `docs/decisions/ferrum-state.md` Q141 and Q142
- A re-check of verdicts: sample only what closes a question (findings are read at acceptance anyway); a verdict data define (an item's, from its lines) goes to a tool for all; the re-checker derives before it reads the line; size per kind by the chance of finding a 5% class, and give an expectation's comparison group enough lines. `docs/decisions/method.md` M30
- A join checked one way hides the other: G6 passed with 18 of 18 deviation rows unannotated. Ask of every join whether both directions are checked. `docs/decisions/ferrum-state.md` Q143
- A blind order a worker must keep (derive, then read): hold it by tools (a reveal that needs the derivation and freezes it) and a hook keyed on `agent_type`, never by care; read a transcript audit's criterion before its count (it missed derivations kept in scratch notes: 23 of 77 shown, not 1). Anchoring hides a disagreement, never makes one: keep non-blind disagreements, redo non-blind agreements. `docs/decisions/method.md` M32
- Classifying a re-check's non-agree rows: re-derive each against its date's rules (a later decision is no overturn), its re-run, and whether the defect was already a finding (then no second sample). `docs/decisions/ferrum-state.md` "Step 4 classified"
- Correcting a class after a sample: a tool where a run or a count decides it (panic texts by a panic hook's backtrace, test labels by comments, items by call ties); a whole blind read only where judgment is the verdict (reachability, mutant equivalence); a shared root relabels its lines together. Below ~20 drawn, a rate says nothing. `docs/decisions/method.md` M33
- A verdict label for a decided result (a test of Ferrum's copy or panic where cm6 differs): `EXCLUDED` with the check, never `EXERCISED`, which claims cm6's behavior; no sweep where no item verdict depends on the label. Q145, same ferrum-state entry
- A cost class where cm6's call is flat because it hands its work to the caller's next step (internal array, engine-deferred copy): judge the pair the caller waits for, both sides, call alone reported. Q144, same entry
- A JS `==` shortcut that keeps identity (`mapped == old ? this`): its only value consequence is signed zero; a `PartialEq` bound on every user type is not worth it, class (b) row with patch. `state.cm6.126.d1`, same entry
