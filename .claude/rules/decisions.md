# Decisions in force for crate code

Decisions that crate code must follow and that reach beyond one cm6 item (`docs/workflow/README.md` §3). Decisions about one cm6 item live in that item's specification row; the design of one crate lives in its `docs/parity/<crate>/design.md`; how cm6 names become Rust names lives in `.claude/rules/rust-naming-decisions.md`. Only the `consultant` agent or the maintainer adds or changes an entry, together with its record in `docs/decisions/foundation.md`. Ids are stable and are what annotations cite (`.claude/rules/rust-crates.md` "Annotations"). `D1`–`D10` are the foundational decisions of `docs/foundation/ferrum-foundation.md` §6; `D11` onward are later ones. Each entry says what it applies to.

| Id | Decision | Reason | Applies to |
|---|---|---|---|
| D1 | A position, length or offset counts UTF-8 bytes of the document, in which every line break counts one whatever separator the source used. A position lies on a `char` boundary; one that does not is a violated precondition (D13). Values recorded from cm6 are UTF-16 code units and are converted through the text they refer to, never by hand; a cm6 fixture whose position falls inside a character has no Ferrum counterpart and is listed | cm6 counts UTF-16 units because that is its runtime's string index; the editor's need is that a position indexes strings and syntax trees directly, which in Rust (`str`, regex, tree-sitter, text shapers) is the byte | every crate: signatures, tests, the fixture replayer |
| D2 | `Text` is cm6's line tree, ported with its shape (leaves of at most 32 lines, `children`), on no library. Lines are stored as given, without their break; a break counts one position. Strings are split on `\r\n?\|\n`, or on the exact `lineSeparator` when one is set, and joined with `"\n"` or that separator. Grapheme clusters follow `@marijn/find-cluster-break` at its pinned version, ported with its table, behind one function, until the improvement `state.imp.001` (the extended grapheme clusters of UAX #29) replaces that rule in the improvement delta of `ferrum-state` (D16) | cm6 exposes the tree's shape and its tests read it; its line strings are what the crates above index. cm6's cluster rules are the floor: they are shown exactly first, and the Unicode rule, which is better for the person editing, then replaces them as a measured difference | `ferrum-state` (`text`, `char`, `column`), every crate that steps by cluster |
| D5 | `StateCommand` is `dyn for<'a> Fn(StateCommandTarget<'a>) -> bool + Send + Sync`, with `StateCommandTarget { state: EditorState, dispatch: &mut dyn FnMut(Transaction) }`; it returns whether it applied, as in cm6. The view-receiving `Command` is decided with `ferrum-view` | cm6's contract (read the state, maybe dispatch, report) and its tests' `{state, dispatch}` literal carry over unchanged | `ferrum-state` `StateCommand`; commands in the crates above |
| D6 | Every public value of the foundation is immutable, cheap to clone and `Send + Sync`; callbacks and values a user supplies are `Send + Sync + 'static`. A foundation crate starts no thread unless its own decision says so, and holds no global mutable state but id counters. A state under construction is visible only on the thread that builds it. Ids follow definition order | cm6's state is already immutable; sharing it lets parsing, search and indexing read a snapshot off the main thread, which cannot be added later without breaking the API | every foundation crate |
| D9 | Licenses per crate: MIT, Apache-2.0 only for a crate that ports or incorporates Apache-2.0 code; the foundation crates are MIT. No copyleft code read, copied or depended on | Decided by the maintainer, 2026-11-04 (`ferrum-foundation.md` §6 D9) | crate manifests, dependencies |
| D11 | cm6's behavior is the floor. It is reproduced as cm6 produces it for every input Ferrum's types can express, including results that look unintended, unless a decision recorded for the item allows a difference. Two kinds of decision do. A *deviation* (`docs/parity/<crate>/raw/decisions.jsonl`), in three classes: (a) cm6 does not terminate; (b) the result needs JavaScript object identity of something that is a value in Rust, or the mutation of an object after it was handed over (a caller's array, an earlier state); (c) the result comes from JavaScript reading past the end of a string or array or computing with `NaN` or `undefined`. An *improvement* (D16) | The floor is what cm6 does, the differential oracle compares every input, and "looks unintended" is not evidence; the three classes are the ones no Rust value can reproduce or no check can assert; an improvement carries evidence of its own | all crate code |
| D12 | Input that exists only because JavaScript is untyped is excluded by type: a position, length, count or index that is negative, fractional, `NaN` or infinite; a value of the wrong type (a non-function where a function is expected, `null` for an object, a string for a number); a key beyond the fields of a typed struct; a string holding a lone surrogate. Positions, lengths and line numbers are `usize`. No API is widened to accept such input | cm6's only guard for these is TypeScript; their results are engine artifacts no caller relies on (no mirrored consumer passes one), and a Rust signature cannot express them | public signatures; which fixtures the replayer runs (`D13` for JSON readers) |
| D13 | Errors. Where cm6 throws on a precondition, Ferrum fails at the same condition: it panics, with the message cm6 gives (its numbers in Ferrum's values), documented under `# Panics`. The exception is a reader of serialized data (`from_json`), which returns `Result<_, Error>` and also returns `Err` for a JSON number outside the domain of `D12`, where cm6 accepts it. Every such failure is a variant of the crate's `Error` enum, whose `Display` is cm6's message; the JavaScript error class (`RangeError`, `Error`) is not ported. Where cm6 fails with an engine `TypeError` on input Ferrum's types can express, Ferrum panics at the same condition with a message of its own. A user callback that fails panics, and the panic propagates | Every explicit throw of cm6 guards a condition its caller can test first, so a failure is a bug of the caller, which Rust reports by panicking (`slice` indexing, `str` slicing); code above this crate derives its positions from the state it holds and returns `bool` (commands), so a `Result` there would be unwrapped at every call. Serialized data comes from outside the program. A non-panicking variant can be added later without breaking callers; the reverse cannot | public signatures, doc comments, the replayer's comparison of errors |
| D14 | Rust forms of JavaScript shapes. A parameter cm6 makes optional is a required parameter: of its own type when cm6's default is a value (the caller writes the default), `Option<T>` when cm6 tells "absent" from every value. An object literal with optional fields is a struct with public fields and `Default`, each default cm6's. A union-typed parameter is an enum or `impl Into<…>` that keeps every member expressible. `===` and `==` on values are the Rust type's `PartialEq`: value equality for numbers, strings and booleans, and a type that cm6 compares by object identity (a function, a definition object such as a facet) implements `PartialEq` by pointer. A callback argument is `Fn`, called in the order and the number of times cm6 calls it, with arguments in cm6's order | One rule per shape keeps signatures mechanical across four crates; a second convenience form of a function is API beyond the specification and can be added later without breaking callers | public signatures |
| D15 | cm6 members marked `@internal` that its tests or the fixtures read. A debug format (`ChangeDesc.toString`) is the type's `Debug` implementation. Anything else is exposed only in a `#[doc(hidden)] pub mod __test`, compiled under the cargo feature `__test` (off by default, never enabled by the facade), named after cm6's own `__test` export; the crate's tests enable it | Ported tests and the replayer live outside the crate and are the same tests as cm6's (`.claude/rules/rust-crates.md` Tests 1, 6); `Debug` output is no API promise in Rust, and a feature keeps internals out of every application build | `@internal` items, `crates/*/tests/` |
| D16 | Improvements over cm6. Where Ferrum can serve the person editing or the embedding application better than cm6 does (correctness, capability, ergonomics), the opportunity is a row of `docs/parity/<crate>/raw/improvements.jsonl`, written by the consultant and never dropped for the sake of imitation: `adopted`, `scheduled` with the point at which it is made, `candidate` with the point at which it is evaluated, or `declined` with a reason other than fidelity to cm6. Code differs from cm6 for the better only under an `adopted` row, annotated `/// cm6 deviation: <what differs>, see <row id>`, and only when the row's reference runs: cm6 with the improvement applied as a patch in the harness, or the test data of the standard the row names, gives the expected values wherever Ferrum and cm6 differ. An improvement that replaces a behavior of cm6 is made as a delta on code already shown equal to cm6, unless making it later would break the public API or stored data, in which case it is part of the crate's design. An implementer who sees a way to do better than cm6 raises it as a question and implements cm6's behavior | The maintainer's intent: cm6 is the floor, never the ceiling, and no way of being better is passed over in silence; a drastic change made in a hurry is not wanted. A reference that runs keeps the proof where it was, and a delta on a proven floor shows that the improvement changed what its row says and nothing else | all crate code; `crates/*/tests/`; the fixture replayer |
