# Decisions in force for crate code

Decisions that crate code must follow and that reach beyond one cm6 item (`docs/workflow/README.md` §3). Decisions about one cm6 item live in that item's specification row; the design of one crate lives in its `docs/parity/<crate>/design.md`; how cm6 names become Rust names lives in `.claude/rules/rust-naming-decisions.md`. Only the `consultant` agent or the maintainer adds or changes an entry, together with its record in `docs/decisions/foundation.md`. Ids are stable and are what annotations cite (`.claude/rules/rust-crates.md` "Annotations"). `D1`–`D10` are the foundational decisions of `docs/foundation/ferrum-foundation.md` §6; `D11` onward are later ones. Each entry says what it applies to.

| Id | Decision | Reason | Applies to |
|---|---|---|---|
| D1 | A position, length or offset counts UTF-8 bytes of the document, in which every line break counts one whatever separator the source used. A position within the document lies on a `char` boundary; one inside a character is a violated precondition (D13). A position beyond the document's end is not D1's: it is clipped, accepted or refused as cm6's code for that call does. Values recorded from cm6 are UTF-16 code units and are converted through the text they refer to, never by hand; a cm6 fixture whose position falls inside a character has no Ferrum counterpart and is listed | cm6 counts UTF-16 units because that is its runtime's string index; the editor's need is that a position indexes strings and syntax trees directly, which in Rust (`str`, regex, tree-sitter, text shapers) is the byte. The boundary rule exists because a byte can fall inside a character; a position past the end falls inside nothing, and what cm6 does with it (clip, keep, throw) is that call's behavior (Q155) | every crate: signatures, tests, the fixture replayer |
| D2 | `Text` is cm6's line tree, ported with its shape (leaves of at most 32 lines, `children`), on no library. Lines are stored as given, without their break; a break counts one position. Strings are split on `\r\n?\|\n`, or on the exact `lineSeparator` when one is set, and joined with `"\n"` or that separator. Grapheme clusters follow `@marijn/find-cluster-break` at its pinned version, ported with its table, behind one function, until the improvement `state.imp.001` (the extended grapheme clusters of UAX #29) replaces that rule in the improvement delta of `ferrum-state` (D16) | cm6 exposes the tree's shape and its tests read it; its line strings are what the crates above index. cm6's cluster rules are the floor: they are shown exactly first, and the Unicode rule, which is better for the person editing, then replaces them as a measured difference | `ferrum-state` (`text`, `char`, `column`), every crate that steps by cluster |
| D5 | `StateCommand` is `dyn for<'a> Fn(StateCommandTarget<'a>) -> bool + Send + Sync`, with `StateCommandTarget { state: EditorState, dispatch: &mut dyn FnMut(Transaction) }`; it returns whether it applied, as in cm6. The view-receiving `Command` is decided with `ferrum-view` | cm6's contract (read the state, maybe dispatch, report) and its tests' `{state, dispatch}` literal carry over unchanged | `ferrum-state` `StateCommand`; commands in the crates above |
| D6 | Every public value of the foundation is immutable, cheap to clone and `Send + Sync`; callbacks and values a user supplies are `Send + Sync + 'static`. A public type whose only use is to carry into one call a callback D14 leaves without bounds (a config `define` consumes, a command's target, an update spec) is no such value: it is not `Send` or `Sync` because of that callback, and the crate's `design.md` names each one. A foundation crate starts no thread unless its own decision says so, and holds no global mutable state but id counters. A state under construction is visible only on the thread that builds it. Ids follow definition order | cm6's state is already immutable; sharing it lets parsing, search and indexing read a snapshot off the main thread, which cannot be added later without breaking the API. A type that only carries an argument into a call is never shared, and is checked through what the call keeps: every value the crate returns or holds is `Send + Sync` | every foundation crate |
| D9 | Licenses per crate: MIT, Apache-2.0 only for a crate that ports or incorporates Apache-2.0 code; the foundation crates are MIT. No copyleft code read, copied or depended on | Decided by the maintainer, 2026-11-04 (`ferrum-foundation.md` §6 D9) | crate manifests, dependencies |
| D11 | cm6's behavior is the floor. It is reproduced as cm6 produces it for every input Ferrum's types can express, including results that look unintended, unless a decision recorded for the item allows a difference. Two kinds of decision do. A *deviation* (`docs/parity/<crate>/raw/decisions.jsonl`), in three classes: (a) cm6 does not terminate, or fails because the JavaScript engine's stack is exhausted (a depth that is the engine's, not cm6's), where Ferrum gives what cm6 gives with a stack large enough and its own recursion whose depth grows with a document or with data made from it (ranges, layers, decorations, syntax nodes, changes) is iterative; (b) the result needs JavaScript object identity of something that is a value in Rust, or the mutation of an object after it was handed over (a caller's array, an earlier state); (c) the result comes from JavaScript reading past the end of a string or array, or computing with `NaN`, with `undefined`, or with the `null` cm6 holds for a value it has not computed; comparing a stored value with the `undefined` of a lookup that found nothing (`null == undefined`) is computing with `undefined`. An *improvement* (D16) | The floor is what cm6 does, the differential oracle compares every input, and "looks unintended" is not evidence; the three classes are the ones no Rust value can reproduce or no check can assert (a stack overflow aborts a Rust process, which no `catch_unwind` of D13 contains); an improvement carries evidence of its own | all crate code |
| D12 | Input that exists only because JavaScript is untyped is excluded by type: a position, length, count or index that is negative, fractional, `NaN` or infinite; a value of the wrong type (a non-function where a function is expected, `null` for an object, a string for a number); a key beyond the fields of a typed struct; a string holding a lone surrogate. A value that cm6's code at that place treats exactly as the absent value is not such input: a `null` it tests with `x == null`, a falsy value where its falsy branch is the absent one, a non-function it calls where calling the absent value throws the same error. It is the absent value, `None` of an `Option` parameter (D14). Nor is a value it reads only for truthiness (`if (x)`, `!x`, `!!x`, `x ? a : b`), as an argument, a member of an object it is given or what a callback returns: it is the `bool` of that test. Nor is a primitive (a number, a boolean, `null`, `undefined`) it reads only through JavaScript's conversion to a string (`String(x)`, a template, `+` with a string, what a `replace` callback returns): it is the string that conversion gives; an object stays excluded, since its conversion calls its own methods. A parameter's default applies first, to `undefined` only. Any other read of such a value (a call where the absent value takes another path, a member read, a comparison) leaves it excluded. Positions, lengths and line numbers are `usize`. No API is widened to accept such input | cm6's only guard for these is TypeScript; their results are engine artifacts no caller relies on (no mirrored consumer passes one), and a Rust signature cannot express them. A value read only through a test or a conversion to a string is no artifact: the language defines both, JavaScript callers rely on them (a `compare` that returns `a && b && …`; `phrase("replaced $ matches", n)`, which every mirrored caller of `phrase` with an argument writes), and a Rust caller writes their result | public signatures; which fixtures the replayer runs (`D13` for JSON readers) |
| D13 | Errors. Where cm6 throws on a precondition, Ferrum fails at the same condition: it panics, with the message cm6 gives (its numbers in Ferrum's values), documented under `# Panics`. The exception is a reader of serialized data (`from_json`), which returns `Result<_, Error>` and also returns `Err` for a JSON number outside the domain of `D12`, where cm6 accepts it. Every such failure is a variant of the crate's `Error` enum, whose `Display` is cm6's message; the JavaScript error class (`RangeError`, `Error`) is not ported. Where cm6 fails with an engine `TypeError` on input Ferrum's types can express, Ferrum panics at the same condition with a message of its own. A user callback that fails panics, and the panic propagates, except where cm6 catches the exception. Data from outside the program enters through a reader that returns `Result`: serialized data, and a position or range a platform or a protocol gives in another unit (an input method's UTF-16 range, an LSP position), whose conversion to D1's unit is such a reader. Where cm6 catches an exception of code an application supplies (`logException` and `EditorView.exceptionSink` of `@codemirror/view`), Ferrum catches the unwinding panic at the same place, with the same consequence, and reports it the same way. A panic that escapes an entry point through which a surface hands the engine an event does not end the application: the engine goes on as cm6 goes on after an uncaught exception in an event handler, which the design of `ferrum-view` derives | Every explicit throw of cm6 guards a condition its caller can test first, so a failure is a bug of the caller, which Rust reports by panicking (`slice` indexing, `str` slicing); code above this crate derives its positions from the state it holds and returns `bool` (commands), so a `Result` there would be unwrapped at every call. Serialized data and a platform's positions come from outside the program, and no caller can test them first. A non-panicking variant can be added later without breaking callers; the reverse cannot. In cm6 no exception ends the editor: the view catches extension code and the browser contains the rest, while a panic that unwinds into a surface's callback from the system aborts the process and the person editing loses the session; immutable states (D6) keep the state before the call intact | public signatures, doc comments, the replayer's comparison of errors; in `ferrum-view` and the surfaces, the places that catch and the entry points of events |
| D14 | Rust forms of JavaScript shapes. A parameter cm6 makes optional is a required parameter: of its own type when cm6's default is a value (the caller writes the default), `Option<T>` when cm6 tells "absent" from every value. An object literal with optional fields is a struct with public fields and `Default`, each default cm6's. A union-typed parameter is an enum or `impl Into<…>` that keeps every member expressible. `===` and `==` on values are the Rust type's `PartialEq`: value equality for numbers, strings and booleans, and a type that cm6 compares by object identity (a function, a definition object such as a facet) implements `PartialEq` by pointer. A callback is called in the order and the number of times cm6 calls it, with arguments in cm6's order: one the crate keeps (a facet's `combine`, a field's `update`, a computed input) is `Fn + Send + Sync + 'static` (D6); one it calls only before the call returns (`iter_changes`, `between`, the callback of `change_by_range`, the `filter` of `RangeSet::update`, a comparator) is `FnMut` or a `&mut` receiver, and `FnOnce` when cm6 calls it once while a definition is made (`provide`, `enables`), with no `Send`, `Sync` or `'static` bound. A parameter or overload that decides whether the result can be absent is two functions (N13). Parameters cm6 reads only together (the second only when the first is given) are one `Option` of a tuple | One rule per shape keeps signatures mechanical across four crates; a second convenience form of a function is API beyond the specification and can be added later without breaking callers (the candidate `state.imp.011`). A callback that never outlives its call is shared with no thread, so D6's reason does not reach it, and the bounds would forbid what cm6's callers do there: collect into a local | public signatures |
| D15 | cm6 members marked `@internal` that its tests or the fixtures read. A debug format (`ChangeDesc.toString`) is the type's `Debug` implementation. Anything else is exposed only in a `#[doc(hidden)] pub mod __test`, compiled under the cargo feature `__test` (off by default, never enabled by the facade), named after cm6's own `__test` export; the crate's tests enable it | Ported tests and the replayer live outside the crate and are the same tests as cm6's (`.claude/rules/rust-crates.md` Tests 1, 6); `Debug` output is no API promise in Rust, and a feature keeps internals out of every application build | `@internal` items, `crates/*/tests/` |
| D16 | Improvements over cm6. Where Ferrum can serve the person editing or the embedding application better than cm6 does (correctness, capability, ergonomics), the opportunity is a row of `docs/parity/<crate>/raw/improvements.jsonl`, written by the consultant and never dropped for the sake of imitation: `adopted`, `scheduled` with the point at which it is made, `candidate` with the point at which it is evaluated, or `declined` with a reason other than fidelity to cm6. Code differs from cm6 for the better only under an `adopted` row, annotated `/// cm6 deviation: <what differs>, see <row id>`, and only when the row's reference runs: cm6 with the improvement applied as a patch in the harness, or the test data of the standard the row names, gives the expected values wherever Ferrum and cm6 differ. An improvement that replaces a behavior of cm6 is made as a delta on code already shown equal to cm6, unless making it later would break the public API or stored data, in which case it is part of the crate's design. An implementer who sees a way to do better than cm6 raises it as a question and implements cm6's behavior | The maintainer's intent: cm6 is the floor, never the ceiling, and no way of being better is passed over in silence; a drastic change made in a hurry is not wanted. A reference that runs keeps the proof where it was, and a delta on a proven floor shows that the improvement changed what its row says and nothing else | all crate code; `crates/*/tests/`; the fixture replayer |
| D17 | Integer domain. Every length and position Ferrum holds is at most `isize::MAX`: a call that would make a longer text or change description from values in memory panics at that call, with a message of Ferrum's own (D13), and a reader of outside data returns `Err` for input whose numbers are each in the domain but whose total (a length, a new length) is not (D13). Arithmetic on held values inside that bound is not checked again. A bound a caller passes that cm6 only compares (the end of a query range, a filter's range, a cursor's start, a size threshold) takes every `usize` and gives the result cm6 gives for that number: code that computes in a signed type converts it so that a value above the signed maximum still compares greater than every position. A position cm6 checks against the document keeps D13's panic for every `usize` | Rust callers write `usize::MAX` for "to the end" as cm6 callers write `1e9`; cm6 only compares such a bound and gives a result, and a cast that wraps turns it into a wrong answer nobody sees. No document is longer than `isize::MAX` bytes, so the bound costs nothing real and makes every later cast in range; cm6 itself is inexact beyond 2^53 | all crate code; conformance verdicts on sentinels and their arithmetic |
