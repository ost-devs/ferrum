# How cm6 names become Rust names: decided cases

Most cm6 names become Rust names by the mechanical conversion of `.claude/rules/rust-crates.md` Architecture 4 (`cursorCharLeft` → `cursor_char_left`). This file decides the cases that conversion does not settle, the interpretive cases listed there: a cm6 member that maps to a std trait or convention, the Rust form of a cm6 static member, any other name that departs from cm6.

Each entry applies to every case its category describes, and only to those; the cm6 column lists the members it covers today in `@codemirror/state` and `@codemirror/view`. A member its category does not describe follows the mechanical conversion, or is a question if that conversion does not settle it (`CLAUDE.md` "Raising a question"). An item named by an entry carries `/// name: see N<n>`; an item an entry adds that cm6 does not export (`is_empty` beside `len`) carries `/// ferrum-only: <reason>, see N<n>` (`.claude/rules/rust-crates.md` "Annotations"). An entry is added or changed only by a decision of the `consultant` agent or the maintainer (`docs/workflow/README.md` §3); its id is stable and is what annotations cite.

| Id | Category | cm6 (covered today) | Rust | Reason |
|---|---|---|---|---|
| N1 | A `length` that measures the value itself | `Text.length`, `Line.length`, `BlockInfo.length` | `len()`, plus `is_empty()` (true when `len() == 0`) | A Rust reader expects `len()` for a value's own size; clippy `len_without_is_empty` (style, warn) requires `is_empty` beside an exported `len`. Not covered: `ChangeDesc.length`, the length of the document before the change, which keeps the mechanical `length()` beside `new_length()`: there `len()` would read as the number of changes, and its `is_empty()` would clash with cm6's `empty` (N4), which is true for a change set with no changes whatever its length (`mirrors/cm6/state/src/change.ts:51`) |
| N2 | A `toString()` that returns the value's content as text | `Text.toString` (the whole document, lines joined with `\n`) | `impl Display`; `to_string()` comes from `ToString` | Ported tests compare `toString()` with literal strings (`mirrors/cm6/state/test/test-text.ts:15`); an inherent `to_string` is a clippy warning (`inherent_to_string`), and an error beside `Display` (`inherent_to_string_shadow_display`, deny). The whole document is built only when the caller formats it, as in cm6 |
| N3 | An `eq(other)` with one parameter, not overridable, computing value equality | `Text.eq` (content) | `impl PartialEq`, and `Eq` when the equality is an equivalence | `==` and std collections use it; an inherent `eq(&self, &Self)` is a clippy warning (`should_implement_trait`). Not covered: an `eq` with more parameters (N5), an `eq` users override (`RangeValue`, `WidgetType`, `GutterMarker`, `LayerMarker`, `Decoration`: question Q6 of `docs/parity/ferrum-state/questions.md`), the static `RangeSet.eq` (question Q3) |
| N4 | A boolean getter `empty` | `SelectionRange.empty` (anchor equals head), `ChangeDesc.empty` (no changes) | `is_empty()`, with cm6's meaning, which its doc comment states | Rust names a boolean predicate `is_…`; the meaning stays cm6's, which for `ChangeDesc` is not "length is zero" |
| N5 | An `eq(other, includeAssoc = false)` | `SelectionRange.eq`, `EditorSelection.eq` | `impl PartialEq` for the default (`includeAssoc` false), plus `eq_including_assoc(&other)` for `includeAssoc` true | `PartialEq::eq` cannot take a third parameter (rustc E0050). An inherent `eq(&self, &Self, bool)` compiles without a clippy warning but shadows `PartialEq::eq` in method calls, so `a.eq(&b)` stops compiling on a type that implements `PartialEq`. cm6's comparison ignores fields (`bidiLevel`, and `assoc` unless asked): `PartialEq` compares exactly what cm6's `eq` compares, and a `Hash`, if any, must agree with it |
