# How cm6 names become Rust names: decided cases

Most cm6 names become Rust names by the mechanical conversion of `.claude/rules/rust-crates.md` Architecture 4 (`cursorCharLeft` → `cursor_char_left`). This file decides the cases that conversion does not settle, the interpretive cases listed there: a cm6 member that maps to a std trait or convention, the Rust form of a cm6 static member, any other name that departs from cm6.

Each entry applies to every case its category describes, and only to those; the cm6 column lists the members it covers today in `@codemirror/state` and `@codemirror/view`. A member its category does not describe follows the mechanical conversion, or is a question if that conversion does not settle it (`CLAUDE.md` "Raising a question"). An item named by an entry carries `/// name: see N<n>`; an item an entry adds that cm6 does not export (`is_empty` beside `len`) carries `/// ferrum-only: <reason>, see N<n>` (`.claude/rules/rust-crates.md` "Annotations"). An entry is added or changed only by a decision of the `consultant` agent or the maintainer (`docs/workflow/README.md` §3); its id is stable and is what annotations cite.

| Id | Category | cm6 (covered today) | Rust | Reason |
|---|---|---|---|---|
| N1 | A `length` that measures the value itself | `Text.length`, `Line.length`, `BlockInfo.length` | `len()`, plus `is_empty()` (true when `len() == 0`) | A Rust reader expects `len()` for a value's own size; clippy `len_without_is_empty` (style, warn) requires `is_empty` beside an exported `len`. Not covered: `ChangeDesc.length`, the length of the document before the change, which keeps the mechanical `length()` beside `new_length()`: there `len()` would read as the number of changes, and its `is_empty()` would clash with cm6's `empty` (N4), which is true for a change set with no changes whatever its length (`mirrors/cm6/state/src/change.ts:51`) |
| N2 | A `toString()` that returns the value's content as text | `Text.toString` (the whole document, lines joined with `\n`) | `impl Display`; `to_string()` comes from `ToString` | Ported tests compare `toString()` with literal strings (`mirrors/cm6/state/test/test-text.ts:15`); an inherent `to_string` is a clippy warning (`inherent_to_string`), and an error beside `Display` (`inherent_to_string_shadow_display`, deny). The whole document is built only when the caller formats it, as in cm6 |
| N3 | An `eq(other)` with one parameter, not overridable, computing value equality | `Text.eq` (content) | `impl PartialEq`, and `Eq` when the equality is an equivalence | `==` and std collections use it; an inherent `eq(&self, &Self)` is a clippy warning (`should_implement_trait`). Not covered: an `eq` with more parameters (N5), an `eq` users override (N10 for `RangeValue`; `WidgetType`, `GutterMarker`, `LayerMarker` and `Decoration` are a question for `ferrum-view`), the static `RangeSet.eq` (N7) |
| N4 | A boolean getter `empty` | `SelectionRange.empty` (anchor equals head), `ChangeDesc.empty` (no changes) | `is_empty()`, with cm6's meaning, which its doc comment states | Rust names a boolean predicate `is_…`; the meaning stays cm6's, which for `ChangeDesc` is not "length is zero" |
| N5 | An `eq(other, includeAssoc = false)` | `SelectionRange.eq`, `EditorSelection.eq` | `impl PartialEq` for the default (`includeAssoc` false), plus `eq_including_assoc(&other)` for `includeAssoc` true | `PartialEq::eq` cannot take a third parameter (rustc E0050). An inherent `eq(&self, &Self, bool)` compiles without a clippy warning but shadows `PartialEq::eq` in method calls, so `a.eq(&b)` stops compiling on a type that implements `PartialEq`. cm6's comparison ignores fields (`bidiLevel`, and `assoc` unless asked): `PartialEq` compares exactly what cm6's `eq` compares, and a `Hash`, if any, must agree with it |
| N6 | A static property holding a definition object that has identity: a facet, a state effect type, an annotation type | `EditorState.tabSize`, `.allowMultipleSelections`, `.lineSeparator`, `.readOnly`, `.phrases`, `.languageData`, `.changeFilter`, `.transactionFilter`, `.transactionExtender`; `Transaction.time`, `.userEvent`, `.addToHistory`, `.remote`; `StateEffect.reconfigure`, `.appendConfig` | An associated constant in SCREAMING_SNAKE_CASE of type `&'static LazyLock<T>`, pointing at a private `static` (`EditorState::TAB_SIZE`); it derefs to `T` wherever `&T` is expected | The object is built at run time (closures, allocation) and must be one object for the whole process, which a `const` value is not and an associated `static` cannot be (Rust has none). The upper case keeps it apart from the instance getter of the same cm6 name (`state.tabSize` → `tab_size()`), a clash an associated function would have. Compiled and run with rustc 1.97, 2026-11-13 |
| N7 | Any other static member: a constructor, a function, a plain value | `EditorState.create`, `.fromJSON`; `Facet.define`; `StateField.define`; `Annotation.define`; `StateEffect.define`, `.mapEffects`; `EditorSelection.single`, `.create`, `.cursor`, `.range`, `.undirectionalRange`, `.fromJSON`; `SelectionRange.fromJSON`; `ChangeSet.of`, `.empty`, `.fromJSON`; `ChangeDesc.fromJSON`; `RangeSet.of`, `.join`, `.iter`, `.compare`, `.eq`, `.spans`, `.empty`; `Text.of`, `.empty` | An associated function with the mechanical name (`Text::of`, `EditorState::create`, `RangeSet::eq`); a static value is a function without parameters (`Text::empty()`, `RangeSet::empty()`) | An associated function is what a Rust reader expects of a constructor, and cm6's name is kept, not `new`. A static `empty` is not the getter of N4. An associated function `eq` with four parameters is not `PartialEq::eq` and raises no clippy warning (tried, clippy 0.1.97) |
| N8 | A cursor: an object advanced by `next` and then read through its fields | `TextIterator.next` (with `value`, `done`, `lineBreak`); `RangeCursor.next` (with `value`, `from`, `to`, `rank`), `RangeCursor.goto` | An inherent method `next` with cm6's parameters; the fields are getters. The type does not implement `Iterator`. Where cm6 also makes the object a JavaScript iterable (`TextIterator`, `Text[Symbol.iterator]`), the Rust type implements `IntoIterator`, so `for` works | cm6's consumers drive these as cursors (`next(skip)`, `goto`), and what they return after the end is specified behavior an `Iterator` cannot express. An inherent `next` beside `Iterator::next` would shadow it in method calls; an inherent `fn next(&mut self) -> Option<T>` is a clippy warning (`should_implement_trait`), while one that returns nothing or takes a parameter is not (tried) |
| N9 | `toJSON` and `fromJSON` | `EditorState`, `EditorSelection`, `SelectionRange`, `ChangeSet`, `ChangeDesc`, `Text.toJSON`; the `toJSON` and `fromJSON` fields of `StateFieldSpec` | `to_json(&self) -> serde_json::Value` and `from_json(&serde_json::Value, …) -> Result<Self, Error>` (D13); `Text::to_json` returns `Vec<String>`, as cm6 returns an array of lines. No `Serialize` or `Deserialize` implementation | cm6's JSON shapes are part of its behavior (history and state persistence read them), and a field's JSON is any JSON value, which `serde_json::Value` is. A serde implementation would be a second serialized form that cm6 does not have |
| N10 | An `eq` users override on a value type that is a generic parameter | `RangeValue.eq` | `PartialEq` as a supertrait of the Rust trait (`trait RangeValue: PartialEq`); cm6's `a.eq(b)` is `a == b`, with the operands in cm6's order | A trait method named `eq` beside `PartialEq::eq` is ambiguous in method calls. cm6's default (identity) and its constructor check have no general Rust form for a value: the implementing type decides its equality, as a cm6 subclass does by overriding `eq`. Not covered: an overridable `eq` on a type used as a trait object (`ferrum-view`) |
| N11 | A parameter typed `1 \| -1` that names a direction of travel | `Text.iter(dir)` | An enum `IterDirection { Forward, Backward }` (cm6's `1` and `-1`), passed where cm6 passes the number; cm6's default `1` is written by the caller (D14) | cm6's type has two members and its code fails or walks in steps for any other number (`mirrors/cm6/state/src/text.ts:444`, `:451`), so the Rust type holds exactly the two (D12, D14). Not `Direction`: `@codemirror/view` exports a `Direction` for text direction. Not a `bool`: `iter(false)` does not say what is false. Not covered: `assoc` and `side` parameters, which are numbers in cm6's signatures (`design.md` §2 of each crate) |
