# Operating notes of the orchestrator

Practices for running Ferrum's work that the maintainer asked for or the orchestrator found, kept in the repository so that every session reads them, on any machine (`docs/workflow/README.md` §5). `/ferrum-run` loads this file. One line per practice: what to do, why, the date. A practice that becomes method moves to the workflow document it belongs to and is removed here. Not for the state of the work (`docs/progress/`) nor for observations about the method (`docs/workflow/learnings.md`).

- State is saved after every worker and every merge, never held for the end of a step: a usage limit, a compaction or a closed session then loses nothing, and no warning that a limit is near is needed (2026-11-13).
- A worker interrupted by a usage limit is resumed with `SendMessage` after the reset; it keeps its context and its unfinished files (`docs/workflow/learnings.md` W22, W31) (2026-11-10).
- Two workers changing the same rows at once: one edits the merged files in place; every other writes only under `.scratch/` one line per change with the row id, the field, its value before and after, and why; the merge checks each value before against the row and stops on a difference (170 changes merged this way with no conflict, W36) (2026-11-12).
- A worker that derives a field afresh gets its rows with that field removed, and compares with the existing values only after writing its own (W28) (2026-11-10).
- A spawn prompt names row keys exactly as the files have them; a key the file lacks stops the worker mid-run (W36) (2026-11-12).
- A script that edits a file by replacing a text asserts that the text is found once: a replace that matches nothing changes nothing and reports nothing; queued questions Q92, Q93 and Q95 were lost that way, because a consultant had changed the line the script looked for (2026-11-16).
- What the work needs that the environment lacks (a toolchain, a tool, a host) is installed for the session where that is quick and written in `dev/maintainer/ambiente.md` for the maintainer to add to the environment; a check or criterion is never chosen because the environment lacks something (the maintainer, `dev/maintainer/instructions/2026-11-19-ambiente-nao-e-criterio.md`) (2026-11-19).
- `str.splitlines()` in Python splits at U+2028 and other separators: a JSONL file with such a character in a value is read with `split('\n')` (a diff of `no-counterpart.jsonl` failed to parse that way) (2026-11-19).
- A worker's stop line (skill item 7) is watched with `python3 tools/ledger.py watch <agent id> --stop <1.5 times the budget>` run by Bash with `run_in_background`, and stopped with TaskStop when the worker returns: it wakes the session once, only if the line is reached; a Monitor is cut at 30 minutes and each line it prints is a request of the whole session's context (2026-11-26).
- A background command of the session is stopped with TaskStop, never with `pkill -f` or waited on with `pgrep -f` and a pattern typed in the same command: the pattern is in that shell's own command line, so it matches itself (a `pkill` killed its own shell with exit 144; a `pgrep` watcher never ended) (2026-11-26).
- A worker cut by the usage limit can be resumed with `SendMessage` only from the session that launched it: after the session's id changed (a compaction that failed at the limit, then `continue`), `SendMessage` answered "No transcript found" though the transcript was on disk; then its undone part goes to a fresh run, and every assignment keeps its rows appended as it goes so that nothing is lost (2026-11-27).
- A message that resumes a worker after a usage limit names no position: the progress line of a task notice can be stale (it said line 44 of U2-r's run while the worker was at line 132), and the worker finds its place from its own rows (2026-11-27).
- A `rechecker` assignment says that every `recheck-derive`, `recheck-reveal`, `recheck-settle` and read is a command of its own: the hook refuses them chained, and the class reads C1 and C2 each lost calls to it (2026-11-27).
