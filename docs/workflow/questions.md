## M22. The checks of a finished stage stop passing when the environment's Node or Rust version moves
- **Found.** On 2026-11-24, at 86b33be, in a fresh container (node 22.23.5, rustc and cargo 1.100.0 stable, nightly 1.102.0 of 2026-11-22): `python3 tools/spec_check.py ferrum-state` fails with "fixtures/text.jsonl is not what its generators write". All 215 differing lines (F0601 onwards) differ only in the field `engine.node` of `input`: `22.23.4` recorded, `22.23.5` regenerated; `engine.unicode` (17.0) and `engine.icu` (78.3) are equal. The generators stamp `process.versions.node` (`docs/parity/ferrum-state/oracle/cm6/text/gen-category.ts:8`, `probe-category.ts:9`). With node 22.23.4 put first on `PATH` for the run, the check ends "checks passed". `python3 tools/impl_check.py ferrum-state handoff --since text=c0ba180,change=ea896a1,rangeset=126dad7,state=efdebd2` fails on one check: "cargo clippy: exit 0, 8 warning(s) or error(s)", all of them "using `chunks_exact` with a constant chunk size" at `crates/ferrum-state/src/change.rs:79`, `:97`, `:131`, `:209`, `:246`, `:287`, `:298`, `:485`. The stage passed handoff whole at rustc 1.97.0 (`docs/progress/ferrum-state.md`). The repository has no `rust-toolchain.toml`, and nothing pins the Node version the harness runs on.
- **Open because.** `docs/workflow/README.md`, `tools/README.md`, `.claude/rules/decisions.md` and `docs/parity/ferrum-state/plan.md` say nothing about which Node or Rust version a check runs on, nor what a check does when that version changes. The `engine` key is descriptive (`docs/parity/ferrum-state/oracle/cm6/text/interp.ts:8`) and spec_check compares fixtures byte for byte. The maintainer's instruction of 2026-11-19 (`dev/maintainer/instructions/2026-11-19-ambiente-nao-e-criterio.md`) says what the work needs from the environment is asked of the maintainer, but does not say whether a version is such a need.
- **Bears on it.** The container's Node and Rust move with no change in the repository, so the same commit passes at one session and fails at the next; a session cannot tell a defect from version drift without diffing by hand, as this one did. The Unicode and ICU versions bear on results (`gen-category.ts:8`, Q7); the Node patch version did not change any result here (deduction from this one diff: only the stamp differed). A newer clippy adds lints to code a finished stage approved; fixing them changes `change.rs` after its checks and code were approved. A Node or rustc version that changes Unicode data would change what Ferrum is compared against (not seen here; not verified for any version). Node 22.23.4 was installed for that session only, outside the repository, and is not on the default `PATH`.
- **Blocks.** The step "Set up a session" of `docs/progress/ferrum-state.md` (spec_check must end with "checks passed") in every new container, and the start of ferrum-state conformance, whose gates run these checks.
- **Raised by.** The orchestrator, 2026-11-24.
