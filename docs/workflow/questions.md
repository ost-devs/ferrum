## M21. A ledger row says at which effort a run was made but not which model made it
- **Found.** The maintainer, reading `docs/progress/ledger.jsonl` on 2026-11-14: a consultant run is recorded as effort `medium`, which is what they configured, but it ran on Fable 5.2 and not on an Opus model; a later reader could take the cost and the result of that row for those of an Opus run at `medium`. Their words, translated: recording the model would be more precise, and would also say later which model was used, since models keep changing (a later Opus, for one). In the file: the 75 `step` rows have the fields `role`, `effort`, `tokens`, `attempts`, `note` and none has a model (`tools/ledger.py`, `KEYS`). The agent definitions name a model by alias (`.claude/agents/consultant.md`: `model: fable`, `effort: medium`; `implementer`, `test-writer`, `spec-auditor`, `verifier`, `cm6-researcher`, `rust-researcher`: `model: opus`, `effort: high`; `translator`: `model: sonnet`), and the orchestrator runs on the model of the session (this one: `claude-fable-5-2`). The rows by role and effort: spec-auditor 38 at `high` and 7 at `medium`, consultant 8 at `high` and 7 at `medium`, verifier 6, cm6-researcher 4, orchestrator 3, rust-researcher 1, implementer 1.
- **Open because.** `docs/workflow/README.md` §5 ("State", "Effort") names tokens, effort and attempts as what a run's row records, and its rule for moving a step to another effort level compares runs "at both levels" without naming the model; E3 compares steps at `medium` with steps at `high` in the same way. No workflow document says which model a role runs on other than the definitions, whose `model:` line can be edited and whose alias the tool resolves.
- **Bears on it.** An alias names a different model as releases come (deduction from the alias form; the mirror's `sub-agents.md` describes the `model` field). What an orchestrator can know of the model a subagent's run was served by was not checked: the task notification of a finished subagent gives tokens, tool uses and duration, and showed no model in this session. For the 75 rows already written, the model is recoverable only as far as the definition's `model:` line at the row's date (git history of `.claude/agents/`) and the session's model say; not verified for any row. The expectations that compare efforts (E3) and budgets set from earlier rows (the pilot review sets U2 to U4 from U1) read these rows.
- **Blocks.** Nothing now; the pilot review and the end-of-stage review read the ledger.
- **Raised by.** The orchestrator, for the maintainer, 2026-11-14.
