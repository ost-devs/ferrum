## Q141. Ferrum has no counterpart for cm6's `null == undefined` when a provider's field dependency is removed
- **Found.** A provider computed from a field, and a reconfiguration that removes that field while its value is null: cm6 compares `oldState.field(dep, false) == state.field(dep, false)` (`mirrors/cm6/state/src/facet.ts:179`, `FacetProvider.dynamicSlot`, `reconfigure`; `mirrors/cm6/state/src/state.ts:68-75` returns `undefined` for a missing field), and since `null == undefined` the getter is not called and the old input is kept. Ferrum takes a present value against a missing field as changed (`crates/ferrum-state/src/facet.rs:1438-1442`) and calls the getter. The U4a verifier's probe (`.scratch/verify-facet/probe`, case 1) with a `StateField<Option<i64>>` holding `None`: getter calls go from 1 to 2 and the facet from `[-1]` to `[-2]`, where by `facet.ts:179` cm6 keeps `[-1]` with no second call (hazard `state.Facet.compute.B8:h1`, `FINDING`, in `raw/conformance-facet.jsonl`). No fixture of chunk `facet` gives a field a null value.
- **Open because.** D14 makes `==` on values the Rust type's `PartialEq`, and Q118 (`design.md` §3) applies it to field values; neither covers a present value against a missing field. D12 makes a value cm6 treats exactly as absent at a place the absent value, but it is written for parameters, and a field in the configuration always holds a `T`. Nothing decides whether `None` of a `StateField<Option<T>>`, or the replayer's null and undefined values, is cm6's null here.
- **Bears on it.** The getter's call count and the facet's input differ, and D14 makes the number of callback calls part of the behavior. Only fields whose value is null or undefined in the state before the reconfiguration are affected. A fixture `{"create": {"const": null}}` in F0055's scenario would show it in the replayer (a deduction); the verifier read `facet.ts:179` and `state.ts:68-75` and did not run the scenario on cm6.
- **Blocks.** The verdict of item `state.cm6.040` (`UNVERIFIED`), and the severity of the finding, from step 3.
- **Raised by.** The U4a verifier (hazards run), 2026-11-26; queued by the orchestrator.

## Q142. A state under construction that a user callback kept, after the build panicked, has no defined behavior
- **Found.** `EditorState` is `Clone` (`crates/ferrum-state/src/state.rs:168-169`), and a field's `create` receives `&EditorState` (`crates/ferrum-state/src/facet.rs:641`). If a callback keeps a clone and a later slot's user function panics, `end_construction` is skipped (`state.rs:652-655`); if the caller catches the panic and uses the clone, `clone.update(&[TransactionSpec::default()]).state()` reaches `unreachable!` at `facet.rs:1342` ("an updated slot has a value in the state it starts from", through `start_value`, `:1338-1344`), and a `StateEffect::RECONFIGURE` that keeps a computed provider reaches `unreachable!` at `facet.rs:1301` ("a slot is read after it is computed", `provider_slot`, `:1431-1432`). The U4a verifier's probe: `.scratch/verify-facet/probe-hz` (lines `src/facet.rs:1342` and `:1301`, kind `panic`, `FINDING`, in `raw/conformance-facet.jsonl`).
- **Open because.** `state.cm6.036.d1` (Q30) decides only that a transaction keeps no half-built state and builds it again on a second `tr.state()`. D6 says a state under construction is visible only on the thread that builds it, and nothing about its use after a failed build. D13 lets the panic propagate and does not forbid catching it. No `# Panics` section states either condition.
- **Bears on it.** By its code, cm6 copies `this.values` with null for the slots it never computed (`mirrors/cm6/state/src/state.ts:121`); its field `update` then receives null (`facet.ts:330-332`), and a provider's `reconfigure` reads `getAddr` as null and keeps it (`facet.ts:173-176`, `:579-581`): a deduction, not run on cm6. Ferrum panics with an internal message instead. A read of the clone's own panicking slot gives "Cyclic dependency" in both (`facet.ts:569-570`, `facet.rs:1281-1282`). Reaching this takes `catch_unwind` around a build in which a callback kept the state; no mirrored consumer does that.
- **Blocks.** The verdict of item `state.cm6.046` (`UNVERIFIED`) and the severity of the findings on `src/facet.rs:1301` and `:1342`, from step 3.
- **Raised by.** The U4a verifier (hazards run, `Compartment` to `combineConfig`), 2026-11-26; queued by the orchestrator.
